API output is provided under the licences of the sources it comes from; no additional database right is claimed over the compilation. Values are normalised on import (names, codes, units; see Normalisation rules), which is a change to the source data for attribution purposes. ## What the sample covers

The fixtures are a demonstration sample, chosen to exercise every importer and every documented behaviour, not to represent the market. A default install (`migrate --seed`) serves only this sample. What that means for the values you see:

| File | What it holds | What it does not mean |
|---|---|---|
| `eea_ro_2024.json` | 182 EEA observations for Romania, 2024 reporting year, at most 13 per make across 15 makes | Not all cars registered in Romania in 2024, not all versions of a model. Of the 182 rows, 32 have no engine capacity (some are electric), 16 no power and 21 no WLTP CO2 |
| `ro_fleet_2025.csv` | 195 passenger-car rows of the DRPCIV fleet file, at most 13 per make, in the file's own order: 186 from Alba county, 5 from Arad, 4 from Argeș | Not national totals. `ro_fleet.count` on a make or model is the sum of the sample's rows for it (Dacia: 13 Alba rows, 10415 vehicles), and `sort=-ro_fleet_count` orders those partial sums |
| `vpic_wmi.json` | 200 WMI rows for 10 manufacturers; the 18 six-character WMIs are rejected by design | Not every WMI in use; a VIN whose WMI is not in the sample decodes with a lower `confidence` |
| `wikidata_manufacturers.json` | 33 SPARQL bindings, merged into 22 Wikidata items | Not every manufacturer; one binding is not one manufacturer |

A live `vehicle:import` of each source replaces the sample for that source. Imports at full size have not been measured (see [known limitations](known-limitations.md) R4 and S6), and v1 responses carry no marker that tells a sample from a full import (S1): record which one you loaded. The [roadmap](roadmap.md) plans coverage metadata in the responses for v2.

## Known data issues
Source values are passed through unmodified apart from the normalisation rules below, so upstream errors reach the API as published. Examples in these fixtures: some EEA rows carry an implausibly low `power_kw` for their engine (for example a 1199 cm³ petrol Dacia Duster at 12 kW), and some commercial names already contain the make (a model named "Fiat 500" under the make Fiat). Report suspected errors to the publisher; the API does not correct them by hand.

## Normalisation rules
1. trim + collapse whitespace; empty → reject "empty"; placeholder tokens → reject "placeholder"; > 120 chars → reject "too_long"
2. aliases (VW → Volkswagen, MERCEDES BENZ → Mercedes-Benz, SKODA → Škoda, CITROEN → Citroën, ROLLS ROYCE → Rolls-Royce)
3. acronyms kept upper-case (BMW, DS, MG, SEAT, MINI, BYD, MAN, DAF, GMC, RAM, MCV, SW, TX, …)
4. everything else Title Case; hyphenated parts title-cased separately
5. models only: strip a trailing engine/drivetrain code (e.g. "2.0 TDI", "1.6 T-GDI", "XDRIVE30D"); ≥ 8 alphanumerics with digits and no space → reject "type_code"
6. identity resolution (ADR 0007): a new slug that already belongs to another live record, or to another record's alias (any kind or record type), rejects the row "slug_collision"; a source reference over 120 characters rejects "ref_too_long". A rejected row is rolled back entirely (a per-row savepoint) and listed in the run's reject report.
7. licence policy: a source whose licence id is not in the admitted list (CC-BY-4.0, OGL-ROU-1.0, CC0-1.0, US-PD) is refused before any write; `vehicle:sources check` repeats the check at release time.
